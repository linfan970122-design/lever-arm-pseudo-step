# P2 lidar ICP yaw vs RTK pseudo-steps — summary

Generated by `analysis/align_lidar_events.py`. Lidar yaw increment comes from
frame-to-frame point-to-plane ICP on /livox/lidar.

**Method: event-windowed, NOT whole-bag.** ICP was run by
`analysis/lidar_icp_yaw_windows.py` only inside [t-3, t+3] s around each event
(overlapping windows merged) plus one contiguous 3000-frame segment per bag taken
from the middle of the bag, which is what the sanity table in (a) is computed on.
Running all 9 bags end to end would have been 233548 frames / ~16 h wall clock.
ICP is strictly frame-to-frame with no accumulation, so skipping the intervals
between events does not change any event's measured rotation; what is lost is
whole-bag coverage, i.e. the sanity statistics in (a) are from a 5-minute sample
per bag rather than the whole run.
